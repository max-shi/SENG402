# xsdata

**xsdata** is a Python library and command-line tool for working with XML, JSON, and related schema-based data formats. It generates Python dataclasses from XML Schema (XSD), WSDL, DTD, and even raw XML/JSON documents, and provides a full-featured binding layer for serializing and parsing data to and from these generated models.

## Features

- **Code generation** from:
  - XML Schema (`.xsd`) definitions
  - WSDL (`Definitions`) service descriptions
  - DTD documents
  - Raw XML/JSON documents (schema inference)
- **Dataclass-based data binding**: parse XML/JSON into typed Python dataclasses and serialize them back
- **Flexible XML parsing** using either `lxml` or the standard library's `xml.sax`/`xml.etree`
- A **command-line interface** (`xsdata`) for generating code and downloading remote schemas
- Rich **type conversion** support for XML Schema datatypes (dates, durations, QNames, binary types, etc.)
- A pluggable **code generation pipeline** built from composable "handlers" that transform an intermediate class model

## Installation

```bash
pip install xsdata[lxml,soap]
```

## Command-Line Usage

Generate Python dataclasses from a schema:

```bash
xsdata generate schema.xsd --package myapp.models
```

Download a schema and all its includes/imports:

```bash
xsdata download http://example.com/schema.xsd --output ./schemas
```

Initialize a project configuration file (`.xsdata.xml`):

```bash
xsdata init-config
```

## Architecture Overview

xsdata's codegen pipeline works in three broad stages:

1. **Parsing** — Source documents (XSD, WSDL, DTD, XML, JSON) are parsed into structured object models:
   - `xsdata.models.xsd.Schema` for XML Schema
   - `xsdata.models.wsdl.Definitions` for WSDL
   - `xsdata.models.dtd.Dtd` for DTDs

2. **Mapping** — "Mapper" classes convert these parsed models into a common intermediate representation, `xsdata.codegen.models.Class` (with `Attr`, `AttrType`, `Extension`, etc.):
   - `SchemaMapper` — XSD → `Class`
   - `DefinitionsMapper` — WSDL → `Class`
   - `DtdMapper` — DTD → `Class`
   - `ElementMapper` / `DictMapper` — infer `Class` models directly from XML/JSON documents

3. **Processing & Generation** — The `ClassContainer` runs an ordered pipeline of `HandlerInterface` implementations (in `xsdata.codegen.handlers`) that resolve references, flatten inheritance, disambiguate names, merge duplicate types, and otherwise normalize the `Class` graph. The result is passed to a `CodeWriter`, which delegates to a registered `AbstractGenerator` (by default `DataclassGenerator`) to render Python source files using Jinja2 templates and the `Filters` helper class.

The top-level orchestrator tying parsing, mapping, and generation together is `xsdata.codegen.transformer.ResourceTransformer`.

### Key classes

| Class | Role |
|---|---|
| `ResourceTransformer` | Entry point: given source URIs, parses, maps, processes, and writes generated code |
| `ClassContainer` | Holds all `Class` objects and runs the codegen handler pipeline |
| `Class`, `Attr`, `AttrType`, `Extension` | Intermediate model representing a dataclass-to-be |
| `DependenciesResolver` | Computes import statements and class ordering per module |
| `CodeWriter` | Dispatches rendering to a registered `AbstractGenerator` |
| `DataclassGenerator` | Default generator producing Python dataclasses via Jinja2 templates |
| `GeneratorConfig` | User-configurable generation settings (naming conventions, structure style, etc.) |

## Data Binding Usage

Once you have generated dataclasses, xsdata provides parsers and serializers to convert between XML/JSON and Python objects.

### Parsing XML

```python
from xsdata.formats.dataclass.parsers import XmlParser
from myapp.models import PurchaseOrder

parser = XmlParser()
order = parser.parse("order.xml", PurchaseOrder)
print(order.customer.name)
```

### Serializing to XML

```python
from xsdata.formats.dataclass.serializers import XmlSerializer
from xsdata.formats.dataclass.serializers.config import SerializerConfig

config = SerializerConfig(pretty_print=True)
serializer = XmlSerializer(config=config)
xml_string = serializer.render(order)
print(xml_string)
```

### Parsing and Serializing JSON

```python
from xsdata.formats.dataclass.parsers import JsonParser
from xsdata.formats.dataclass.serializers import JsonSerializer

parser = JsonParser()
order = parser.from_path("order.json", PurchaseOrder)

serializer = JsonSerializer()
print(serializer.render(order))
```

### Using a SOAP-style client

```python
from xsdata.formats.dataclass.client import Client, Config

config = Config.from_service(MyServicePort)
client = Client(config=config)
response = client.send(request_obj)
```

## Programmatic Code Generation

```python
from xsdata.codegen.transformer import ResourceTransformer
from xsdata.models.config import GeneratorConfig

config = GeneratorConfig.create()
config.output.package = "myapp.models"

transformer = ResourceTransformer(config=config)
transformer.process(["schema.xsd"])
```

This will parse `schema.xsd`, run it through the full codegen pipeline (attribute resolution, circular-reference detection, enumeration handling, class renaming, etc.), and write the resulting Python dataclass modules to disk.

## Datatype Utilities

xsdata ships with rich value types mirroring XML Schema primitives, useful both in generated code and standalone:

```python
from xsdata.models.datatype import XmlDate, XmlDuration

d = XmlDate.from_string("2024-01-15")
duration = XmlDuration("P1Y2M10D")
print(duration.years, duration.months, duration.days)
```

## Extensibility

- Register custom type converters via `ConverterFactory.register_converter`
- Register custom code generators via `CodeWriter.register_generator`
- Register alternate class backends (e.g. attrs, pydantic) via `ClassTypes.register`
- Swap XML parsing backends between `lxml`-based and native handlers (`LxmlEventHandler` / `XmlEventHandler`)
