# camunda-dmn-model

`camunda-dmn-model` is a Java library for reading, creating, modifying, and writing [DMN (Decision Model and Notation)](https://www.omg.org/spec/DMN/) 1.1/1.3-style XML models. It provides a strongly-typed, object-oriented view over the DMN XML schema, allowing you to work with DMN diagrams (decisions, decision tables, business knowledge models, input data, etc.) as Java objects instead of manipulating raw XML.

The library is built on top of the generic model API (`org.camunda.bpm.model.xml`), following the same pattern used by other Camunda model libraries (e.g. the BPMN model API). Every element of the DMN specification is represented by a Java interface with a corresponding implementation class, and elements can be freely traversed, created, and connected via their getters and setters.

## Key Concepts

### Entry point: `Dmn`

The `Dmn` class is the main entry point of the library. It offers static utility methods to:

- Read a `DmnModelInstance` from a `File` or `InputStream`
- Write a `DmnModelInstance` to a `File` or `OutputStream`
- Convert a model to a `String` and back
- Validate a model
- Create a new, empty DMN model from scratch

```java
DmnModelInstance modelFromFile = Dmn.readModelFromFile(new File("decision.dmn"));
DmnModelInstance emptyModel = Dmn.createEmptyModel();
Dmn.writeModelToFile(new File("out.dmn"), modelFromFile);
String xml = Dmn.convertToString(modelFromFile);
Dmn.validateModel(modelFromFile);
```

### `DmnModelInstance`

`DmnModelInstance` represents a parsed or in-memory DMN model. It extends the generic `ModelInstance` and exposes the model's root element:

```java
public interface DmnModelInstance extends ModelInstance {
    Definitions getDefinitions();
    void setDefinitions(Definitions definitions);
    DmnModelInstance clone();
}
```

All navigation into a DMN document starts from `getDefinitions()`.

### `Definitions` — the model root

`Definitions` is the root element of any DMN model and provides access to all top-level content:

- `getImports()` — externally imported models
- `getItemDefinitions()` — reusable type definitions
- `getDrgElements()` — the Decision Requirements Graph elements (`Decision`, `InputData`, `BusinessKnowledgeModel`, `KnowledgeSource`)
- `getArtifacts()` — diagram artifacts (`Association`, `TextAnnotation`)
- `getElementCollections()` — groupings of DRG elements
- `getBusinessContextElements()` — business context metadata (`OrganizationUnit`, `PerformanceIndicator`, etc.)

Plus metadata such as `getNamespace()`, `getExpressionLanguage()`, `getTypeLanguage()`, `getExporter()`, and `getExporterVersion()`.

### DRG Elements

`DrgElement` is the common supertype for elements that make up a Decision Requirements Graph:

- **`Decision`** — a decision node, holding an `Expression` (typically a `DecisionTable`), requirement relationships (`InformationRequirement`, `KnowledgeRequirement`, `AuthorityRequirement`), and business-context links (`OrganizationUnit`s as decision makers/owners, `PerformanceIndicator`s, etc.). Also carries Camunda-specific extensions such as `getCamundaHistoryTimeToLive()`/`setCamundaHistoryTimeToLive(Integer)` and `getVersionTag()`.
- **`InputData`** — represents external input data used by decisions, exposing an `InformationItem` describing its type.
- **`BusinessKnowledgeModel`** — reusable decision logic, defined via an `EncapsulatedLogic` (a `FunctionDefinition`), with its own `KnowledgeRequirement`s and `AuthorityRequirement`s.
- **`KnowledgeSource`** — represents authoritative sources of knowledge, linked via `AuthorityRequirement`.

Additionally, `DecisionService` groups decisions into input/output/encapsulated decisions and referenced input data.

### Expressions

`Expression` is the base type for all DMN expression constructs:

- **`DecisionTable`** — the most common expression type, containing `Input` and `Output` clauses and a set of `Rule`s. Configurable via `HitPolicy`, `BuiltinAggregator`, and `DecisionTableOrientation`.
- **`LiteralExpression`** — a literal value/expression with optional `ImportedValues`.
- **`Context`** / **`ContextEntry`** — key/value expression contexts.
- **`Invocation`** and **`Binding`** — invoking a `FunctionDefinition` with bound parameters.
- **`FunctionDefinition`** — parameterized reusable logic, with `FormalParameter`s and a body `Expression`.
- **`List`** — an ordered list of expressions.
- **`Relation`** — a table-like structure of `Column`s and `Row`s.

### Decision Tables in Detail

A `DecisionTable`:

- `getInputs()` — `Input` clauses, each with an `InputExpression` and optional `InputValues` (allowed values)
- `getOutputs()` — `Output` clauses, each with a name, type, `OutputValues`, and optional `DefaultOutputEntry`
- `getRules()` — `Rule`s, each holding ordered `InputEntry` and `OutputEntry` collections (unary tests / literal expressions matching the inputs/outputs)
- `getHitPolicy()` / `setHitPolicy(HitPolicy)` — e.g. `UNIQUE`, `FIRST`, `PRIORITY`, `COLLECT`, etc.
- `getAggregation()` / `setAggregation(BuiltinAggregator)` — used with `COLLECT` hit policy (`SUM`, `COUNT`, `MIN`, `MAX`)

### Business Context Elements

`BusinessContextElement` and its subtypes model organizational and performance metadata attached to decisions:

- **`OrganizationUnit`** — decision makers/owners, via `getDecisionsMade()` / `getDecisionsOwned()`
- **`PerformanceIndicator`** — impacted KPIs, via `getImpactingDecisions()`

### Artifacts

`Artifact` (and subtypes `Association`, `TextAnnotation`) represent non-semantic diagram elements used to annotate or visually connect DRG elements.

### Extensibility

Every `DmnElement` may carry `ExtensionElements`, which supports adding arbitrary or typed extension elements:

```java
ExtensionElements extensionElements = decision.getExtensionElements();
MyCustomExtension ext = extensionElements.addExtensionElement(MyCustomExtension.class);
```

### Querying

The generic `Query<T>` interface (backed by `QueryImpl`) is returned from certain accessors (e.g. `ExtensionElements.getElementsQuery()`) and supports:

- `list()` — materialize results as a `List<T>`
- `count()` — number of results
- `filterByType(Class<V>)` / `filterByType(ModelElementType)` — narrow results by type
- `singleResult()` — retrieve exactly one result

### Error Handling

`DmnModelException` is thrown for DMN-model-related errors (parsing, validation, invalid structure, etc.).

## Usage Examples

### Reading and inspecting a DMN file

```java
import org.camunda.bpm.model.dmn.Dmn;
import org.camunda.bpm.model.dmn.DmnModelInstance;
import org.camunda.bpm.model.dmn.instance.*;

import java.io.File;
import java.util.Collection;

DmnModelInstance modelInstance = Dmn.readModelFromFile(new File("dish-decision.dmn"));

Definitions definitions = modelInstance.getDefinitions();
System.out.println("Model name: " + definitions.getName());

Collection<DrgElement> drgElements = definitions.getDrgElements();
for (DrgElement element : drgElements) {
    if (element instanceof Decision) {
        Decision decision = (Decision) element;
        System.out.println("Decision: " + decision.getName());

        Expression expression = decision.getExpression();
        if (expression instanceof DecisionTable) {
            DecisionTable table = (DecisionTable) expression;
            System.out.println("  Hit policy: " + table.getHitPolicy());
            System.out.println("  Number of rules: " + table.getRules().size());
        }
    }
}
```

### Building a DMN model from scratch

```java
import org.camunda.bpm.model.dmn.*;
import org.camunda.bpm.model.dmn.instance.*;

import java.io.File;

DmnModelInstance modelInstance = Dmn.createEmptyModel();

Definitions definitions = modelInstance.newInstance(Definitions.class);
definitions.setId("definitions");
definitions.setName("sample-decisions");
definitions.setNamespace("http://camunda.org/schema/1.0/dmn");
modelInstance.setDefinitions(definitions);

Decision decision = modelInstance.newInstance(Decision.class);
decision.setId("decision1");
decision.setName("Approve Loan");
definitions.getDrgElements().add(decision);

DecisionTable decisionTable = modelInstance.newInstance(DecisionTable.class);
decisionTable.setHitPolicy(HitPolicy.UNIQUE);
decision.setExpression(decisionTable);

Input input = modelInstance.newInstance(Input.class);
InputExpression inputExpression = modelInstance.newInstance(InputExpression.class);
inputExpression.setTypeRef("number");
input.setInputExpression(inputExpression);
decisionTable.getInputs().add(input);

Output output = modelInstance.newInstance(Output.class);
output.setName("approved");
output.setTypeRef("boolean");
decisionTable.getOutputs().add(output);

Dmn.validateModel(modelInstance);
Dmn.writeModelToFile(new File("loan-decision.dmn"), modelInstance);
```

### Working with requirements between decisions

```java
import org.camunda.bpm.model.dmn.instance.*;

// Link a decision to required input data
InformationRequirement requirement = modelInstance.newInstance(InformationRequirement.class);
requirement.setRequiredInput(inputDataElement);
decision.getInformationRequirements().add(requirement);

// Link a decision to a required business knowledge model
KnowledgeRequirement knowledgeRequirement = modelInstance.newInstance(KnowledgeRequirement.class);
knowledgeRequirement.setRequiredKnowledge(businessKnowledgeModel);
decision.getKnowledgeRequirements().add(knowledgeRequirement);
```

### Serializing a model to a String

```java
String dmnXml = Dmn.convertToString(modelInstance);
System.out.println(dmnXml);
```

## Error Handling

Operations that fail due to invalid model structure or parsing issues throw `DmnModelException`:

```java
try {
    DmnModelInstance instance = Dmn.readModelFromFile(new File("broken.dmn"));
    Dmn.validateModel(instance);
} catch (DmnModelException e) {
    System.err.println("Invalid DMN model: " + e.getMessage());
}
```
