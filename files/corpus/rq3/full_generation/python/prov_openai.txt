# prov

`prov` is a Python library for creating, reading, transforming, visualizing, and serializing provenance documents.

The API models provenance as a document containing entities, activities, agents, and the relations between them—for example, an activity using an input entity to generate an output entity. It provides support for namespaces and qualified identifiers, multiple serialization formats, graph conversion, and DOT-based visualization.

## Installation

Install the package with your preferred Python package manager:

```bash
pip install prov
```

## Quick start

Create a provenance document, declare entities and an activity, connect them with provenance relations, and serialize the result:

```python
from prov.model import ProvDocument

document = ProvDocument()
document.add_namespace("ex", "https://example.org/")

input_file = document.entity(
    "ex:input",
    other_attributes={"prov:label": "Input dataset"},
)

process = document.activity(
    "ex:process",
    startTime="2024-01-10T09:00:00",
    endTime="2024-01-10T09:05:00",
    other_attributes={"prov:label": "Data processing"},
)

output_file = document.entity(
    "ex:output",
    other_attributes={"prov:label": "Processed dataset"},
)

document.usage(process, input_file)
document.generation(output_file, process)
document.derivation(output_file, input_file, activity=process)

json_text = document.serialize(format="json")
print(json_text)
```

A `ProvDocument` is also a `ProvBundle`, so document-level APIs for records, namespaces, and relations can be used directly on a document.

## Core concepts

### Documents and bundles

- **`ProvDocument`** is the top-level provenance container.
- **`ProvBundle`** is a container for provenance records and namespaces.
- A document may contain nested bundles through `ProvDocument.add_bundle()` and `ProvDocument.bundle()`.

Both documents and bundles can:

- Register namespaces.
- Create elements and relations.
- Retrieve records.
- Produce a PROV-N representation.
- Merge or normalize content.
- Produce a DOT plot.

```python
from prov.model import ProvDocument

document = ProvDocument()
document.add_namespace("ex", "https://example.org/")

bundle = document.bundle("ex:run-1")
bundle.entity("ex:artifact")
```

Use the container inspection methods when working with nested provenance:

```python
if document.has_bundles():
    for bundle in document.bundles():
        print(bundle.identifier())
```

### Identifiers and namespaces

The library uses `Identifier`, `QualifiedName`, and `Namespace` to represent provenance identifiers.

- `Identifier.uri()` returns the identifier URI.
- `Identifier.provn_representation()` returns a PROV-N-oriented representation.
- `QualifiedName` provides a namespace and local part.
- `Namespace` maps a prefix to a URI and can create qualified names.

```python
from prov.identifier import Namespace

example = Namespace("ex", "https://example.org/")
item = example.qname("item")

print(item.uri())
print(item.provn_representation())
```

Namespaces can be added to a document or bundle:

```python
document.add_namespace("ex", "https://example.org/")
document.set_default_namespace("https://example.org/default/")
```

Use `valid_qualified_name()` when an identifier may not resolve, or `mandatory_valid_qname()` when a valid qualified name is required:

```python
qname = document.valid_qualified_name("ex:output")

if qname is not None:
    print(qname.uri())
```

### Elements

The main provenance elements are:

- **`ProvEntity`** — a thing, artifact, dataset, file, or other resource.
- **`ProvActivity`** — a process or action occurring over time.
- **`ProvAgent`** — a person, organization, software system, or other responsible actor.

Create them through a bundle or document:

```python
dataset = document.entity("ex:dataset")
workflow = document.activity(
    "ex:workflow",
    startTime="2024-01-10T09:00:00",
    endTime="2024-01-10T09:10:00",
)
researcher = document.agent("ex:researcher")
```

Elements support convenience methods for creating common relationships:

```python
workflow.used(dataset)

result = document.entity("ex:result")
result.wasGeneratedBy(workflow)
result.wasAttributedTo(researcher)

workflow.wasAssociatedWith(researcher)
```

### Relations

Relations describe how elements are connected. Most relation methods accept an optional relation identifier and optional extra attributes.

| Method | Relationship created |
|---|---|
| `generation(entity, activity, time=...)` | An entity was generated by an activity |
| `usage(activity, entity, time=...)` | An activity used an entity |
| `start(activity, trigger, starter, time=...)` | An activity started |
| `end(activity, trigger, ender, time=...)` | An activity ended |
| `invalidation(entity, activity, time=...)` | An entity was invalidated |
| `communication(informed, informant)` | One activity was informed by another |
| `attribution(entity, agent)` | An entity was attributed to an agent |
| `association(activity, agent, plan)` | An activity was associated with an agent and optional plan |
| `delegation(delegate, responsible, activity)` | An agent acted on behalf of another |
| `influence(influencee, influencer)` | One element influenced another |
| `derivation(generatedEntity, usedEntity, ...)` | An entity was derived from another |
| `revision(...)` | A derivation representing revision |
| `quotation(...)` | A derivation representing quotation |
| `primary_source(...)` | A derivation representing primary-source use |
| `specialization(specificEntity, generalEntity)` | An entity specializes another |
| `alternate(alternate1, alternate2)` | Two entities are alternates |
| `mention(specificEntity, generalEntity, bundle)` | An entity mentions another in a bundle |
| `membership(collection, entity)` | An entity belongs to a collection |

Example:

```python
source = document.entity("ex:source")
derived = document.entity("ex:derived")
activity = document.activity("ex:transform")
agent = document.agent("ex:service")

document.usage(activity, source)
document.generation(derived, activity)
document.derivation(derived, source, activity=activity)
document.association(activity, agent)
document.attribution(derived, agent)
```

## Working with records

Every provenance item is a `ProvRecord`. Records provide common inspection APIs:

```python
for record in document.records():
    print("Type:", record.get_type())
    print("Identifier:", record.identifier())
    print("Attributes:", record.attributes())

    if record.is_element():
        print("This is an element.")
    elif record.is_relation():
        print("This is a relation.")
```

Useful record methods include:

- `identifier()` — retrieve the record identifier, if present.
- `get_type()` — retrieve the record’s provenance type.
- `get_asserted_types()` and `add_asserted_type()` — inspect or add asserted types.
- `get_attribute()` — retrieve values for an attribute.
- `attributes()` — retrieve all attributes.
- `label()` — retrieve a label.
- `value()` — retrieve a value.
- `get_provn()` — render the record in PROV-N form.
- `copy()` — make a copy of a record.

Retrieve records from a document or bundle:

```python
all_records = list(document.get_records())

entities = list(document.get_records(class_or_type_or_tuple=type(dataset)))

matching = document.get_record("ex:dataset")
```

## Attributes and literals

Most creation methods accept `other_attributes`, and relationship methods also accept `attributes` or `other_attributes` depending on the API.

```python
entity = document.entity(
    "ex:report",
    other_attributes={
        "prov:label": "Final report",
        "ex:version": "2",
    },
)
```

`Literal` represents a value together with optional datatype and language information:

```python
from prov.model import Literal

literal = Literal("example value")
print(literal.value())
print(literal.datatype())
print(literal.langtag())
print(literal.provn_representation())
```

The record utilities also include helpers for typed values:

```python
from prov.model import (
    encoding_provn_value,
    parse_boolean,
    parse_xsd_datetime,
)

timestamp = parse_xsd_datetime("2024-01-10T09:00:00")
enabled = parse_boolean("true")

print(encoding_provn_value(True))
```

## Serialization and deserialization

`ProvDocument.serialize()` serializes a document to text, a path-like destination, or an open stream. If no destination is supplied, it returns a string.

```python
json_text = document.serialize(format="json")
```

Write a document to a file:

```python
document.serialize("provenance.json", format="json")
```

Deserialize from a path or stream with `ProvDocument.deserialize()`:

```python
from prov.model import ProvDocument

loaded = ProvDocument.deserialize(
    source="provenance.json",
    format="json",
)
```

The package-level `read()` helper loads a provenance document from a string, bytes value, or path-like object:

```python
import prov

document = prov.read("provenance.json", format="json")
```

Available serializer classes include:

- `ProvJSONSerializer`
- `ProvNSerializer`
- `ProvRDFSerializer`
- `ProvXMLSerializer`

The serializer registry can resolve a serializer class by format name:

```python
from prov.serializers import get

serializer_class = get("json")
serializer = serializer_class()
```

### RDF options

`ProvRDFSerializer` accepts an RDF output format:

```python
document.serialize(
    "provenance.trig",
    format="rdf",
    rdf_format="trig",
)
```

The same option can be used while reading RDF:

```python
document = ProvDocument.deserialize(
    source="provenance.trig",
    format="rdf",
    rdf_format="trig",
)
```

### XML options

`ProvXMLSerializer.serialize()` accepts a `force_types` option:

```python
document.serialize(
    "provenance.xml",
    format="xml",
    force_types=True,
)
```

## PROV-N output

Use `get_provn()` to obtain a textual PROV-N representation.

```python
print(document.get_provn())
```

The method is also available on individual records:

```python
for record in document.records():
    print(record.get_provn())
```

## Graph conversion

Convert a provenance document to a NetworkX directed multigraph with `prov_to_graph()`:

```python
from prov.graph import prov_to_graph

graph = prov_to_graph(document)

print(graph.number_of_nodes())
print(graph.number_of_edges())
```

Convert a compatible `networkx.MultiDiGraph` back into a provenance document:

```python
from prov.graph import graph_to_prov

round_tripped_document = graph_to_prov(graph)
```

## DOT visualization

Generate a DOT graph with `prov_to_dot()`:

```python
from prov.dot import prov_to_dot

dot = prov_to_dot(
    document,
    show_nary=True,
    use_labels=True,
    direction="BT",
    show_element_attributes=True,
    show_relation_attributes=True,
)

dot.write_png("provenance.png")
```

A bundle or document can also plot itself directly:

```python
document.plot(
    filename="provenance.png",
    show_nary=True,
    use_labels=True,
    show_element_attributes=True,
    show_relation_attributes=True,
)
```

## Document transformations

### Flatten bundles

Create a flattened document representation:

```python
flat_document = document.flattened()
```

### Unify records

Obtain a unified provenance container:

```python
unified_document = document.unified()
```

### Merge content

Merge records and related content from another bundle or document:

```python
other = ProvDocument()
other.add_namespace("ex", "https://example.org/")
other.entity("ex:additional-artifact")

document.update(other)
```

## Error handling

The base library error is `prov.Error`. Additional public exception types include:

- `ProvException`
- `ProvExceptionInvalidQualifiedName`
- `ProvElementIdentifierRequired`
- `ProvJSONException`
- `ProvRDFException`
- `ProvXMLException`
- `DoNotExist`

For example:

```python
import prov
from prov.model import ProvExceptionInvalidQualifiedName

try:
    document.mandatory_valid_qname("unknown:item")
except (prov.Error, ProvExceptionInvalidQualifiedName) as exc:
    print(f"Unable to resolve identifier: {exc}")
```

## Command-line helpers

The package also exposes command-line-oriented helpers:

- `prov.scripts.convert.convert_file()` and `main()`
- `prov.scripts.compare.main()`

These APIs accept argument lists through their `main(argv=...)` functions and return integer status codes.
