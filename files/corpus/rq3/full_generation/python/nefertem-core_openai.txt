# nefertem-core

`nefertem-core` is a Python library for organizing data-quality and data-observability workflows around **runs**, **resources**, **stores**, and extensible **plugins**.

Its API supports several workflow types:

- **Inference** — infer schemas or metadata from data resources.
- **Profiling** — generate profiles using supported profiling frameworks.
- **Metrics** — calculate metrics and produce metric reports.
- **Validation** — evaluate constraints and produce validation reports.
- **Persistence** — write metadata and generated artifacts to an output store.
- **Input stores and readers** — retrieve data from local, remote, S3, SQL, or custom sources.

The library is designed around a plugin model, allowing framework-specific integrations to provide execution, report rendering, and artifact generation.

## Core workflow

A typical workflow has the following stages:

1. Create a `Client`.
2. Configure input and output stores.
3. Create a `Run` from resource and run-configuration dictionaries.
4. Execute the relevant run operation, such as validation, profiling, inference, or metric collection.
5. Persist produced data, metadata, reports, and artifacts.

```text
Client
  ├── stores
  └── create_run(...)
        └── Run
              ├── plugins
              ├── readers
              ├── reports/results
              └── output store
```

## Installation

Install the package and any plugins required for the frameworks you intend to use.

```bash
pip install nefertem-core
```

Framework-specific integrations may require additional packages.

## Quick start

Create a client with an output location, then create a run from resource and run configuration dictionaries.

```python
from nefertem_core.client.builder import create_client

client = create_client(output_path="./nefertem-output")

resources = [
    {
        # Resource configuration supplied by your application.
    }
]

run_config = {
    # Run configuration supplied by your application.
}

run = client.create_run(
    resources=resources,
    run_config=run_config,
    experiment="example-experiment",
    run_id="example-run",
)

# Persist data generated by the run.
run.persist_data()
```

`resources` and `run_config` are dictionaries because they are interpreted by the configured run and plugin builders. Their exact contents depend on the workflow and installed integrations.

## Client API

### `create_client`

```python
create_client(
    output_path: str | None = None,
    stores: list[dict] | None = None,
) -> Client
```

Creates a `Client`.

- `output_path` configures the output destination.
- `stores` optionally provides input-store configurations during client creation.

```python
from nefertem_core.client.builder import create_client

client = create_client(output_path="./output")
```

### `Client`

```python
class Client:
    def add_store(self, config: dict) -> None:
    def create_run(
        self,
        resources: list[dict],
        run_config: dict,
        experiment: str | None = None,
        run_id: str | None = None,
        overwrite: bool = False,
    ) -> Run:
```

#### Add an input store

```python
client.add_store(
    {
        # Store configuration.
    }
)
```

#### Create a run

```python
run = client.create_run(
    resources=resources,
    run_config=run_config,
    experiment="daily-checks",
    run_id="2025-03-08",
    overwrite=False,
)
```

An experiment name and run ID allow output to be grouped and identified by the configured output store.

## Runs

`Run` is the base object returned by `Client.create_run`.

```python
class Run:
    def persist_data(self) -> None:
```

Use `persist_data()` to persist data associated with the run.

```python
run.persist_data()
```

Specialized run types add workflow-specific operations.

| Run type | Main operation | Output-oriented operations |
|---|---|---|
| `RunInference` | `infer()` | `log_schema()`, `persist_schema()` |
| `RunProfiling` | `profile()` | `log_profile()`, `persist_profile()` |
| `RunMetric` | `metric(metrics)` | `log_metric()`, `persist_metric()` |
| `RunValidation` | `validate(constraints, error_report)` | `log_report()`, `persist_report()` |

### Inference runs

`RunInference` supports schema and framework inference.

```python
class RunInference(Run):
    def infer_framework(self) -> list[Any]:
    def infer_nefertem(self) -> list[NefertemSchema]:
    def infer(self) -> tuple[list[Any], list[NefertemSchema]]:
    def log_schema(self) -> None:
    def persist_schema(self) -> None:
```

Example:

```python
# When the created run is configured as an inference run:
framework_results, schemas = run.infer()

run.log_schema()
run.persist_schema()
```

### Profiling runs

`RunProfiling` produces framework-specific profile results and Nefertem profile reports.

```python
class RunProfiling(Run):
    def profile_framework(self) -> list[Any]:
    def profile_nefertem(self) -> list[NefertemProfile]:
    def profile(self) -> tuple[list[Any], list[NefertemProfile]:
    def log_profile(self) -> None:
    def persist_profile(self) -> None:
```

Example:

```python
framework_profiles, profiles = run.profile()

run.log_profile()
run.persist_profile()
```

### Metric runs

`RunMetric` measures configured metrics against resources.

```python
class RunMetric(Run):
    def metric_framework(self, metrics: list[dict]) -> list[Any]:
    def metric_nefertem(self, metrics: list[dict]) -> list[NefertemMetricReport]:
    def metric(
        self,
        metrics: list[dict],
    ) -> tuple[list[Any], list[NefertemMetricReport]]:
    def log_metric(self) -> None:
    def persist_metric(self) -> None:
```

Example:

```python
metrics = [
    {
        # Metric configuration.
    }
]

framework_metrics, metric_reports = run.metric(metrics)

run.log_metric()
run.persist_metric()
```

### Validation runs

`RunValidation` evaluates configured constraints. The `error_report` argument defaults to `"partial"`.

```python
class RunValidation(Run):
    def validate_framework(
        self,
        constraints: list[dict],
        error_report: str | None = "partial",
    ) -> list[Any]:

    def validate_nefertem(
        self,
        constraints: list[dict],
        error_report: str | None = "partial",
    ) -> list[NefertemReport]:

    def validate(
        self,
        constraints: list[dict],
        error_report: str | None = "partial",
    ) -> Any:

    def log_report(self) -> None:
    def persist_report(self) -> None:
```

Example:

```python
constraints = [
    {
        # Constraint configuration.
    }
]

validation_result = run.validate(
    constraints=constraints,
    error_report="partial",
)

run.log_report()
run.persist_report()
```

## Stores

Stores provide the boundary between Nefertem workflows and external data or output destinations.

### Input stores

The base `InputStore` API supports both file-oriented and native retrieval.

```python
class InputStore:
    def fetch_file(self, src: str) -> Path:
    def fetch_native(self, src: str) -> Any:
    def clean_paths(self) -> None:
```

Available input-store types include:

- `DummyInputStore`
- `LocalInputStore`
- `RemoteInputStore`
- `S3InputStore`
- `SQLInputStore`

Return values vary by store type:

| Store | `fetch_file()` | `fetch_native()` |
|---|---|---|
| `LocalInputStore` | `Path` | `Path` |
| `RemoteInputStore` | `Path` | `str` |
| `S3InputStore` | `str` | `str` |
| `SQLInputStore` | `Path` | `str` |
| `DummyInputStore` | `None` | `None` |

### Output stores

Output stores initialize run destinations, log metadata, and persist artifacts.

```python
class OutputStore:
    def init_run(self, exp_name: str, run_id: str, overwrite: bool) -> None:
    def get_run_path(self) -> str:
    def log_metadata(self, obj: dict, filename: str) -> None:
    def persist_artifact(self, obj: Any, filename: str) -> None:
```

`LocalOutputStore` provides local filesystem persistence and returns `Path` values for its path-producing methods.

```python
class LocalOutputStore(OutputStore):
    def init_run(self, exp_name: str, run_id: str, overwrite: bool) -> None:
    def get_run_path(self) -> Path:
    def log_metadata(self, obj: dict, filename: str) -> Path:
    def persist_artifact(self, obj: Any, filename: str) -> Path:
```

### Store builder

`StoreBuilder` builds and retrieves configured stores.

```python
class StoreBuilder:
    def build_output_store(self, path: str | None = None) -> None:
    def build_input_store(
        self,
        temp_dir: str,
        config: dict | None = None,
    ) -> None:
    def get_input_store(self, name: str) -> InputStore:
    def get_all_input_stores(self) -> list[InputStore]:
    def get_output_store(self) -> OutputStore:
```

Convenience retrieval functions are also available:

```python
get_input_store(name: str) -> InputStore
get_all_input_stores() -> list[InputStore]
get_output_store() -> OutputStore
```

## Readers

Readers adapt an `InputStore` to a representation needed by a plugin.

```python
class DataReader:
    def fetch_data(self, src: str) -> Any:
```

Built-in reader types include:

- `FileReader` — retrieves a `Path`.
- `NativeReader` — retrieves a native value from the store.
- `PandasDataFrameDuckDBReader` — reads data into a pandas `DataFrame`, including DuckDB queries.
- `PandasDataFrameSQLReader` — reads SQL data into a pandas `DataFrame`.
- `PandasDataFrameFileReader` — reads file-backed data into a pandas `DataFrame`.

Create a reader with `build_reader`:

```python
build_reader(
    reader_type: str,
    store: InputStore,
    **kwargs,
) -> DataReader
```

Example:

```python
from nefertem_core.readers.builder import build_reader

reader = build_reader(
    reader_type="file",
    store=input_store,
)

path = reader.fetch_data("data.csv")
```

Reader names and additional keyword arguments are determined by the configured reader registry and integration.

## Plugins

Plugins perform the framework-specific work for an inference, profiling, metric, or validation operation.

```python
class Plugin:
    def setup(self, *args, **kwargs) -> None:
    def execute(self) -> dict:
    def render_nefertem(self, obj: Result) -> RenderTuple:
    def render_artifact(self, obj: Result) -> list[RenderTuple]:
    def framework_name() -> str:
    def framework_version() -> str:
    def get_framework(self) -> dict:
```

A plugin generally follows this lifecycle:

1. `setup(...)` receives readers, resources, constraints or metrics, and execution arguments.
2. `execute()` performs the operation.
3. `render_nefertem(...)` converts execution output into a Nefertem report.
4. `render_artifact(...)` produces artifacts for persistence.

### Plugin builders

Plugin builders create plugin instances for a workflow.

```python
class PluginBuilder:
    def build(self, *args, **kwargs) -> list[Plugin]:
```

A builder factory is available for constructing builders from run configuration and stores:

```python
builder_factory(config: RunConfig, stores: dict) -> list
```

Workflow-specific base builders include:

- `InferencePluginBuilder`
- `ProfilingPluginBuilder`
- `MetricPluginBuilder`
- `ValidationPluginBuilder`

## Results and reports

Plugins work with `Result` objects and report models.

```python
class Result:
    def to_dict(self) -> dict:
```

`ExecutionStatus` and `ResultType` are enumerations used to classify plugin execution and result data.

The following report classes can be serialized with `to_dict()`:

- `Blob`
- `Env`
- `NefertemBaseReport`
- `RunInfo`
- `ProfileMetric`
- `NefertemSchema`
- `NefertemMetricReport`
- `NefertemProfile`
- `NefertemReport`

Example:

```python
report_data = report.to_dict()
```

## Errors

The library defines a base exception and specialized store and run errors:

```python
class NefertemError(Exception):
class StoreError(NefertemError):
class RunError(NefertemError):
```

Validation-specific errors are represented by:

```python
class ValidationError(NefertemError):
```

Handle Nefertem errors at the application boundary:

```python
try:
    run.persist_data()
except NefertemError as exc:
    print(f"Nefertem operation failed: {exc}")
```

## Extending nefertem-core

To add support for another framework or data source:

1. Implement an `InputStore` or `DataReader` for a new source type.
2. Implement a workflow-specific `Plugin`.
3. Implement a corresponding `PluginBuilder`.
4. Register custom readers or stores using `ReaderRegistry`, `InputStoreRegistry`, or `OutputStoreRegistry`.
5. Return framework output through `Result`, Nefertem reports, and artifact render tuples.

The registry APIs are:

```python
class ReaderRegistry(dict):
    def register(self, name: str, module: str, class_name: str) -> None:
```

```python
class InputStoreRegistry(dict):
    def register(
        self,
        kind: str,
        store: InputStore,
        model: StoreConfig,
    ) -> None:
```

```python
class OutputStoreRegistry(dict):
    def register(self, kind: str, store: OutputStore) -> None:
```

This architecture allows applications to use a common run and persistence model while selecting the data stores, readers, validation engines, profiling tools, metric engines, and inference frameworks appropriate for their environment.
